## 核心操作规则

### 投递简历（`btn_apply` / `id/btn_apply`）

| 项目 | 内容 |
|------|------|
| **规则** | 只有当**用户和 HR 双方都发过消息**后，聊天页才会出现"投递简历"按钮 |
| **来源** | `[官方]` Boss直聘帮助中心 |
| **UI 表现** | 按钮在聊天输入框上方出现；职位详情页和未互动聊天页均不显示 |
| **代码影响** | `can_apply()` 检测此按钮；必须从 `navigate_to_chat()` 打开的聊天页调用，不能从职位详情页调用 |

**正确工作流（两阶段）**：

```
第一阶段（boss_greet_task.py）：搜索职位 → 发打招呼（立即沟通）
         ↓ 等待数小时至一天，HR 回复
第二阶段（boss_apply_task.py）：消息Tab → get_message_list() → navigate_to_chat() → can_apply() → apply_to_job()
```

#### 补充：每日 150 次沟通上限（2026-10-21 实测）

上面那条"免费沟通名额"是**弹窗**形态。还有一条**独立的、以 toast 呈现**的限制，
2026-10-21 跑到当天第 ~150 次「立即沟通」时触发：

| 项目 | 内容 |
|------|------|
| **规则** | 每天最多与 **150 位** BOSS 沟通 |
| **来源** | `[实测]`（2026-10-21，账号当天累计 148 条已发出 + 若干次点开未发成功的尝试） |
| **UI 表现** | **没有弹窗**，只有 toast：「您今天已与150位BOSS沟通，休息一下，明天再来吧～」。聊天页**会正常打开**（转圈 loading），约 3 秒后 toast 出现、聊天页自动关闭退回职位详情页 |
| **toast 文案拿不到** | `uiautomator dump` 不含 toast 窗口；`dumpsys notification` 只有 toast 队列无文案；`logcat` 只有 `E/Toast: setGravity()`。**不能靠读文案判定** |
| **代码影响** | 靠**前台 Activity** 判定：`smart_match_greet._open_chat_page()` —— 首轮等 3s 未见 `editText` 时查 `dumpsys window` 的 `mCurrentFocus`；**已回 `JobDetailActivity`**（聊天页被自动关闭）→ 判定触顶，**第 1 次即终止整轮**并截图取证；**仍是 `ChatRoomActivity`** → 慢渲染，延长 5s（累计 8s）重试，救回候选。`ChatLoadGuard`（连续 3 次失败）保留为前台 Activity 取不到时的兜底 |
| **取证** | toast 只存活约 3s，故在首轮等待失败的**当场**截图（`logs/boss/screenshots/chat_probe_*.png`），晚一步就拍不到了 |
| **计数口径** | Boss 数的是**沟通次数**（点开聊天即计数，含没发成功的）；脚本按**实际发出**计数，所以脚本会略早于 Boss 触顶退出——方向是安全的 |

> 早期记录（2026-10-12）"Boss 无公布每日上限"已被本次实测推翻，
> `candidate_profile.yaml: daily_hard_limit` 已从 `0` 改为 `150`。
>
> **2026-10-22 补充**：原先把「触顶」和「慢渲染」都当成「加载超时」，导致触顶要空转 3 次才收工、
> 慢渲染则直接丢候选。判定改为看**前台 Activity**（见上表「代码影响」行）。

#### 补充：uiautomator dump 在聊天页会挂死（2026-10-22 实测）

| 项目 | 内容 |
|------|------|
| **现象** | Boss 聊天页上 `adb shell uiautomator dump` 可能长时间不返回。设备端 `uiautomator` 进程停在 `R`（运行中）状态一直等 idle（聊天页动画/webview 永不到 idle），本地 adb 客户端跟着挂住 |
| **影响** | `wait_for_element()` 的超时**救不了**——它卡在单次 dump 调用内部，整个脚本无限期阻塞 |
| **代码影响** | `ADBRunner.shell()` 加 `timeout` 形参（超时返 `(False, "TIMEOUT")`）；`AndroidSkill._adb()` 透传 timeout；`get_ui_hierarchy()` 的 dump 带 **25s 超时**，超时/失败后 `killall -9 uiautomator` 清设备端残留，且**不再 cat** 陈旧的 `window_dump.xml`（会让 `wait_for_element` 误判元素存在） |
| **未覆盖** | `skills/linkedin/linkedin_automation_skill.py:219` 还有一处裸 `uiautomator dump`（无超时），未纳入本次修复 |

### 登录态要求

| 项目 | 内容 |
|------|------|
| **规则** | 搜索/查看职位无需登录，但发送消息、投递简历等操作需已登录 |
| **来源** | `[实测]` |
| **UI 表现** | 弹出登录对话框，含文字"立即登录" / "请登录后操作" |
| **代码影响** | `DialogType.LOGIN_REQUIRED`；检测到时停止自动化并通知用户 |

---

### 职位状态（已下线）

| 项目 | 内容 |
|------|------|
| **规则** | 已关闭招聘的职位无法进行沟通操作 |
| **来源** | `[实测]` |
| **UI 表现** | 弹窗含"该职位已下线" / "职位已下线" / "暂停招聘" |
| **代码影响** | `DialogType.JOB_OFFLINE`；跳过该职位，继续处理下一个 |

## 弹窗检测快速参考

`DialogType._SIGNATURES`（`skills/boss/boss_automation_skill.py`）通过文本包含匹配识别弹窗：

| 弹窗类型 | 关键词 |
|---------|--------|
| `DAILY_LIMIT` | `"免费沟通名额已使用完"` / `"今日免费沟通"` / `"名额已用"` |
| `LOGIN_REQUIRED` | `"立即登录"` / `"请登录后操作"` |
| `JOB_OFFLINE` | `"该职位已下线"` / `"职位已下线"` / `"暂停招聘"` |
| `EXISTING_CHAT` | `"已和对方建立沟通"` |

## 页面导航规则

- **消息Tab**：底部第三个 Tab（`cl_tab_3`），文字为"消息"
- **消息列表**：展示所有已沟通的联系人，`contact_vp` 容器内的 `RecyclerView`
- **进入聊天**：点击联系人条目（用坐标 `tap_x/tap_y`），不能通过 resource-id 直接定位
