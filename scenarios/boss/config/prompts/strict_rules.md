严格模式维度评分指引：

**ai_native 维度**
- JD 正文出现 Vibe Coding / Claude Code / Cursor / AI 辅助编程等词汇 → 高分（8-10）
- JD 正文提到 AI 工具、产品思维、Agent 等与候选人相关要素 → 中高分（6-8）
- JD 正文完全没有上述要素，说明公司只需要传统工程深度 → 低分（1-3）

**role_fit 维度**
- 评分必须以 JD 正文内容为准，不以岗位标题判断；标题写「工程师」不等于与候选人无关，关键看 JD 实际要求什么能力
- 候选人具备通过 Vibe Coding 独立完成全栈项目的真实能力（React/TS + Python/FastAPI），有多个完整项目上线；「Vibe Coding 可胜任」的岗位不应低分
- 岗位若为传统工程深度（精通 Java/Go/C++/算法框架/音视频底层/嵌入式），与候选人方向明显错位 → 低分（1-3）
- 初创公司（天使轮/A轮）且明确需要 0 到 1 产品搭建 → 与候选人高度契合，role_fit 应为高分（8-10）

**skill_match 维度**
- 候选人核心优势：AI 工具 / Vibe Coding 全栈交付、产品设计、Design System、抽象思维、审美、沟通表达、学习能力；JD 有对应则高分
- 后端能力边界：FastAPI/Supabase 为轻量级服务，不等同于专业后端经验（无 Spring/Go/Java 生产系统、无高并发/分布式深度）；若 JD 将后端列为核心硬性要求，应如实反映在该维度的低分中
- 候选人审美好（设计学硕士 + 企业级 Design System 实战）、沟通强（售前蓝图演示 + 客户需求挖掘）、抽象思维强；AI 原生环境中这些优势可弥补工程深度不足

**basic_fit 维度**
- 用工性质优先：全职正式岗满分；实习 / 兼职 / 外包 / 按天计薪 / 在校生优先 → 0-1 分
- 薪资低于候选人期望下限 30% 以上 → 该维度低分
- 硬性要求产品经验 3 年以上（候选人仅 2 年）→ 该维度适当低分
- 强制要求特定垂直行业深度经验（候选人无该行业经历）→ 该维度低分；若为加分项或优先项则不影响
- 「大厂背景优先」或明确招 P7/P8+ → 该维度适当低分

**growth_fit 维度**
- 差距为软性（如行业经验、某框架熟悉度）且候选人有跨领域快速上手记录 → 高分
- 差距为硬性工程深度（语言/框架年限等无法短期弥补的能力）→ 低分
