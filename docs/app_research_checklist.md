# App 自动化研究清单

> **强制要求**：在为任何 App 开始 UI 探索或功能开发之前，必须完成本清单。
> 完成后将结论写入 `scenarios/<app>/docs/<app>_platform_rules.md`。

---

## 必须研究的来源

| 优先级 | 来源 | 目的 |
|--------|------|------|
| ★★★ | **官方帮助中心 / FAQ** | 用户操作规则、功能前提条件、每日限制 |
| ★★★ | **App 内「帮助」或「使用规则」页面** | 平台强制规定，通常比官网更新 |
| ★★☆ | **开放平台 / 开发者文档**（如有）| API 接口、速率限制、回调机制 |
| ★★☆ | **社区 / 论坛 / GitHub Issues** | 其他人踩过的坑、隐性限制 |
| ★☆☆ | **抓包分析**（Fiddler / Charles）| 接口字段、状态码含义 |

## 核心问题清单

在正式探索 UI 之前，回答以下问题：

### 功能前提条件
- [ ] 哪些按钮/功能在特定条件下才出现？（例：需要双方互动、需要完成某步骤）
- [ ] 哪些操作需要双方都执行后才能触发？
- [ ] 是否有"首次使用"或"引导流程"会遮挡正常 UI？

### 速率与限制
- [ ] 是否有每日次数上限？（发送消息、投递简历、浏览等）
- [ ] 超出限制时如何表现？（弹窗？静默失败？）
- [ ] 操作之间是否需要间隔时间？

### 账号与权限
- [ ] 哪些功能需要登录态？未登录时如何跳转？
- [ ] 哪些功能是付费/会员专属？
- [ ] 是否有账号等级/信誉影响功能可用性？

### 反自动化
- [ ] 是否有滑块验证码、图形验证码？触发条件是什么？
- [ ] 是否检测操作频率？连续快速操作会封号吗？
- [ ] 是否检测设备指纹或 ADB 特征？

### 页面与导航
- [ ] 各主要页面如何跳转？有没有"只能从特定页面进入"的限制？
- [ ] 弹窗/对话框的触发场景有哪些？
- [ ] 是否有"后台刷新"导致 UI 状态不稳定的情况？

## 输出物要求

完成研究后，在 `scenarios/<app>/docs/<app>_platform_rules.md` 中记录：

1. **核心限制**：每条规则的来源（官方文档/实测/社区）
2. **触发条件**：限制被触发时的 UI 表现（弹窗文字、页面变化）
3. **代码影响**：对应的 `DialogType`、`PageState` 或处理逻辑
4. **待验证项**：尚不确定的规则，标注 `TODO`

## 经验教训（Lessons Learned）

> 在这里记录因"未研究文档就开始探索"而付出的代价，避免重蹈覆辙。

- **Boss直聘 btn_apply 事件（2026-09）**：
  `btn_apply`（投递简历）在 UI 探索阶段始终不可见，被误标为"unconfirmed"。
  实际原因：平台规定双方互发消息后才显示该按钮，帮助中心有明确说明。
  **后果**：设计出错误的 apply/greet 互斥分支，白费多轮探索和开发。
  **教训**：先读官方帮助中心，再开始 UIAutomator XML dump。
